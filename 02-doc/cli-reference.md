# CLI Command Reference

Generated by reading the actual command registry (`command_dispatcher.py` +
`commands/*_commands.py`) rather than hand-written from memory — this is the
verified, current syntax as of 2026-08-04, not a proposal. `README.md`'s
"Available Commands" section and `docs/_index.txt` predate this and disagree
with it in several places (see `04-tasks/chores.md`); trust this file over
those until they're replaced.

Known design inconsistencies in this syntax (redundant directional commands,
inconsistent start/stop/status shapes, etc.) are tracked separately in
`03-features/notdone/F21-cli-syntax-orthogonality.md` — not fixed here.
Two commands below are documented **exactly as they currently behave**,
including that they are no-ops: `intent.explore`/`scene.explore`-adjacent and
`scene.count`.

## Syntax

```
<domain> <action> [<subaction>] [args...]
```

Tokens are matched positionally: 1 token = bare domain command, 2 tokens
tries `domain.action`, 3+ tokens tries `domain.action.subaction` first, then
falls back to `domain.action` with the 3rd token as an argument. Trailing
tokens are the command's parameters, filled **by position, not by name** —
there is no `--flag value` syntax anywhere in this CLI. Any full word or its
listed abbreviation may be used for the domain/action/subaction tokens;
abbreviations do not apply to argument values.

Value parsing for arguments: `true`/`yes`/`1` → `True`, `false`/`no`/`0` →
`False`, digits → `int`, digits with a `.` → `float`, otherwise left as a
string (this is `parse_value()` — see `04-tasks/chores.md` for a bug where
this collides with numeric `config.set` values).

## Movement — `move.*`, `turn.*`

Abbreviations: `move`→`m`, `turn`→`t`, `forward`→`fwd`, `backward`→`bak`,
`distance`→`dis`, `time`→`tim`, `clockwise`→`clk`,
`counterclockwise`→`ccw`, `degrees`→`deg`, `radians`→`rad`.

| Command | Args | Description |
|---|---|---|
| `move forward <meters>` | `meters: float` | Move forward (sign ignored — always forward) |
| `move backward <meters>` | `meters: float` | Move backward (sign ignored — always backward) |
| `move time <seconds>` | `seconds: float` | Move forward for a duration |
| `turn radians <radians>` | `radians: float` | Turn by signed angle, radians |
| `turn clockwise <degrees>` | `degrees: float` | Turn clockwise (sign ignored) |
| `turn counterclockwise <degrees>` | `degrees: float` | Turn counterclockwise (sign ignored) |
| `turn time <seconds>` | `seconds: float` | Turn for a duration |

## Control — `robot.*`

Abbreviations: `robot`→`r`, `stop`→`stp`, `status`→`sts`.

| Command | Args | Description |
|---|---|---|
| `robot stop` | none | Halt movement immediately (direct `cmd_vel`, not via `/intent`) |
| `robot status` | none | Configured speeds, launch-process status, ROS2 API node status |
| `robot speak <text>` | `text: str` (remaining tokens joined) | Speak text aloud via speech output |
| `robot subsystems` | none | Running/not-running status for `gendrv`/`nav`/`semantic`/`control`/`mission`/`vision`, detected via a `ps aux` keyword grep per subsystem; `mission`'s row also shows its live FSM state (`IDLE`/`EXPLORING`/etc., read from `/mission/state`, `"unknown"` if nothing is published within ~1s) |

## Map — `map.*`

Abbreviations: none for `map`; `save`→`sav`, `list`→`lst`, `serialize`→`ser`.

| Command | Args | Description |
|---|---|---|
| `map save` | none | Save current map to `maps/`, using the `map_name` config variable — **not** a filename argument |
| `map list` | none | List saved maps |
| `map serialize` | none | Save current map in SLAM Toolbox serialized format, using `map_name` |

## Mission — `mission.*`

No abbreviation for `mission`; `start`→`sta`, `stop`→`stp`, `status`→`sts`
apply to the third token. Renamed from `nav` (F21 D3a) — every command in
this domain talks to `dome_mission`, not to navigation logic in
`dome_control`.

| Command | Args | Description |
|---|---|---|
| `mission go start <label>` | `label: str` | Navigate to the nearest confirmed object with this label (publishes `navigation_go` to `/intent`, owned by `dome_mission`) |
| `mission go stop` | none | Cancel the current navigation goal (publishes `navigation_cancel`) |
| `mission explore start` | none | Start autonomous frontier exploration (publishes `exploration_start`) |
| `mission explore stop` | none | Stop exploration (publishes `exploration_stop`) |
| `mission explore status` | none | Read `/explore/status` (shells out to `ros2 topic echo --once`, 3s timeout) |

## Launch — `launch.*`

Abbreviations: `launch`→`lch`, `list`→`lst`, `info`→`inf`, `start`→`sta`,
`stop`→`stp`.

| Command | Args | Description |
|---|---|---|
| `launch list` | none | List available launch templates |
| `launch info <launch_type>` | `launch_type: str` | Show details for a launch template |
| `launch start <launch_type> [use_sim_time] [map] [map_name]` | `launch_type: str` required; `use_sim_time: bool`, `map: str`, `map_name: str` optional | Start a launch process. **Optional args are positional, in this exact order** — there is no way to supply `map_name` without also supplying `use_sim_time` and `map` first |
| `launch stop <launch_type>` | `launch_type: str` | Stop a running launch process |

## System — `system.*`

Abbreviations: `system`→`sys`, `topics`→`top`, `ps`→`ps`, `launches`→`lau`,
`kill`→`kil`.

| Command | Args | Description |
|---|---|---|
| `system topics` | none | List active ROS2 topics |
| `system ps` | none | List ROS-related OS processes |
| `system kill <pid>` | `pid: int` | Kill a ROS process by PID |
| `system launches` | none | List `ros2 launch` processes |

| Command | Args | Description |
|---|---|---|

## Config — `config.*`

Abbreviations: `config`→`c`, `set`→`set`, `get`→`get`, `list`→`lst`.

| Command | Args | Description |
|---|---|---|
| `config set <name> <value>` | `name: str`, `value: str` | Set a config variable — see `04-tasks/chores.md` for a bug where `0`/`1` values are stored as booleans, not numbers |
| `config get <name>` | `name: str` | Read a config variable |
| `config list` | none | List all config variables |

## Survey — `survey.*`

No abbreviation for `survey`.

| Command | Args | Description |
|---|---|---|
| `survey start` | none | Start a 360° spin survey to build the semantic map. No `survey stop`/`survey status` exist. |

## Scene / behavior — `scene.*` (publishes to `/intent`, handled by `behavior_manager`)

No abbreviation for `scene`. These commands bypass normal parameter
validation (published with **no slots**, regardless of extra tokens typed) —
this is a known bug tracked in `04-tasks/chores.md`.

| Command | Args | Description | Status |
|---|---|---|---|
| `scene describe` | ignored | Describe the current scene via `/describe_scene` service | Works |
| `scene count <object_type>` | typed, then **silently dropped** | Count visible objects by type | **No-op.** `PerceptionBehavior` only logs `count_objects intent not yet implemented`; the argument never reaches it regardless |
| `scene objects` | ignored | List currently detected objects (from cached `/oak/detections`) | Works |

## `intent.*` (deprecated duplicates of `scene.*` — do not use)

`intent.stop`, `intent.explore`, `intent.describe_scene`,
`intent.count_objects`, `intent.list_objects` all exist and dispatch
successfully, but are exact duplicates of `robot.stop`/`scene.*` (same
`/intent` payload) plus one command with no `scene.*` equivalent:

| Command | Status |
|---|---|
| `intent stop` | Works — duplicates `robot.stop`'s effect via a different path (`/intent` → `behavior_manager` → `MotionBehavior`, which also just halts `cmd_vel`) |
| `intent explore` | **No-op.** `MotionBehavior.execute` has `elif intent.name == "explore": pass  # not yet implemented`. Live exploration is `mission.explore.start`, a different intent (`exploration_start`) |
| `intent describe_scene` | Works, duplicates `scene describe` |
| `intent count_objects` | **No-op**, same stub as `scene count` |
| `intent list_objects` | Works, duplicates `scene objects` |

Slated for removal — see `04-tasks/chores.md`.

## General

| Command | Description |
|---|---|
| `help` | Show common commands |
| `help commands` | Show all registered commands, alphabetically |
| `help <command> [<subcommand>]` | Show detailed help if a matching file exists in `docs/`, else list matching subcommands |
| `exit` / `quit` / `q` / `x` | Exit the CLI |
